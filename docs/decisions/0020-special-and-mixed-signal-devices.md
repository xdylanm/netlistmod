# 0020 — Special and mixed-signal devices

- **Status:** proposed (2026-11-10; accepted when M17 closes)
- **Date:** 2026-11-10
- **Context:** M17 adds the last planned letters: ngspice's code models (A) and OSDI devices (N), with the `.model` values code models need, and LTspice's special functions (A), frequency response analyzer (`@`) and its probe (`&`). The maintainer decided section 2 of [m17-tasks.md](../design/m17-tasks.md) on 2026-11-10; this record carries those decisions. The probes behind them are in section 3.1 of that list and in `tests/solver/test_ngspice_special_probes.py` and `tests/solver/test_ltspice_special_probes.py`, on ngspice 47 and LTspice 26.1.1.
- **Decision:**
  1. **The ngspice digital U is a named v1 exclusion.** Its libraries are written for PSpice compatibility mode, where `$` is a name character (`$G_DPWR`, `$D_HI`) and the ngspice grammar reads a comment; ngspice runs a line without its I/O model, so the line's shape does not tell where its nodes end; and LOGICEXP and PINDLY have keyword sections the manual does not describe. Every U line that is not a URC line keeps raising `UnsupportedConstruct`, by decision 0019 item 7's shape rule, with the construct "ngspice digital U device, out of scope for v1". ngspice U stays `supported` with milestone `M16`. This amends plan section 8, point 2. *Considered:* an M17b before M18.
  2. **Nodes.** `CodeModelDevice` (ngspice A: `model`, `ports`), `OsdiDevice` (N: `model`, instance parameters in `params`), `SpecialFunction` (LTspice A: `function`, an `Identifier`, with `inputs`, `outputs` and `common` properties), `FrequencyAnalyzer` (`@`: `impedance`, the `zm` flag or `None`; `reference_net` and `intermediate_net`) and `FraProbe` (`&`: `analyzer`, with `output_pair` and `input_pair`). No shared base class: A is a different device in each dialect. *Considered:* `XspiceDevice`; one `SpecialDevice` with optional fields.
  3. **LTspice A's function names are the 13 that LTspice's own symbols write**, case-insensitive, a closed list: `BUF`, `AND`, `OR`, `XOR`, `SCHMITT`, `DFLOP`, `SRFLOP`, `VARISTOR`, `MODULATOR`, `OTA`, `PHASEDET`, `COUNTER` and `SAMPLEHOLD`. Any other name is a `ParseError` at the name, which names the function its symbol writes. This is an exception to decision 0002: the reference's symbol names (INV, SCHMTBUF, SCHMTINV, MODULATE) stop LTspice ("Expected valid special function name"). *Considered:* only the nine behind the reference's symbols; any name.
  4. **ngspice A's ports** are read by their own rules, so the node class of every other element does not widen (§6.3 rule 9). After the designator come the ports, then the model, the last name on the line. A port is a connection or a vector `[ … ]`; a connection is an optional port type of Table 8.1 (any case) and one node, two for a differential type, with or without parentheses; or `null`; or `%vnam` and a source. A digital node may carry `~` with no blank after it. A port type may stand before a vector and applies to each of its untyped connections; with a differential type each such connection is a pair (§8.1.1 Example 1). `ports` is a tuple of `CodeModelPort` (`vector`, `connections`, `span`, `port_type`), each connection a `CodeModelConnection` (`port_type` as written, `nodes`, `inverted`, `null`, `source`). `nodes` is every node in order, without `null` and `%vnam` sources. A `%vnam` source is a controlling reference, like F's and H's (decision 0015 item 3): resolved, `UNRESOLVED_ELEMENT` when missing, a `control` signature entry, not a net. The signature gains a `ports` entry per A line: each port's position, vector flag and type, and each connection's type, nodes and `null`; `~` is left out. Not checked: the port count and types and where `null` may stand. Refused: a comma inside a vector or inside parentheses and `~` before a blank (ngspice runs them), `%vnam` inside a vector, a name=value on the line and a number as the model (ngspice stops). *Considered:* `nodes` only; `ports` without a signature entry.
  5. **`.model` values for code models.** A `.model` whose type is not a built-in SPICE type of `model-types.json` may give a vector (`[`, values separated by blanks, over `+` lines, `]`: a `ValueList` whose span takes the brackets), `TRUE` or `FALSE` (any case, an `Identifier`) and a quoted string (`file="…"`, a `Formula` with the `"` delimiter, never read as an expression). On a built-in type each stays a `ParseError`; a comma between vector values is refused. Parameter names are not checked. `model-types.json` moves to the model package, which the parser reads it from; the document layer's model-type check reads the same table. *Considered:* only the types of §8.2 to §8.5; quoted strings as formulas.
  6. **ngspice N (§9.3.1.6):** nodes, then the model by decision 0014's boundary rule, then named parameters; at least one node, the count unchecked; a number as the model, a positional value after it and a flag are refused. A and N take a model whose type is not built in: a built-in one is `MODEL_TYPE_MISMATCH`, and `set_model` checks it. NG-OSD-001 is `validated` with the `r2_cmc.osdi` that the Windows build of ngspice 47 ships; the solver tests set `NGSPICE_OSDI_DIR` from the install and skip with a reason when the model is missing.
  7. **LTspice A and `@` parameters.** A: exactly eight nodes, the function, then named parameters, open names, in LTspice's value slot, separated by blanks; a comma before a parameter (LTspice runs it), a bare name in a value, a positional value and a flag are refused. `@`: two nodes, then `zm` (once) and the reference's parameters in any order, a closed list; `flist=`, `pp=`, `nmax=` and `ac=` take a list (`ValueList`), blank-separated; a comma before a parameter or `zm`, or between list values, is refused as on every LTspice element line (decision 0009), except `ac=`'s magnitude and phase (`ac=1,0`, the reference's form); none is required. `refnode=` and `intnode=` name nets: node references (`UNRESOLVED_NODE`), not terminals and not in the signature, editable with `set_param`. *Considered:* `refnode=` and `intnode=` as connections.
  8. **`&` and its analyzer.** `FraProbe.analyzer` is an `ElementReference` to `@` and the probe's suffix (any case), resolved in the probe's scope; unresolved is `UNRESOLVED_ELEMENT`, except when the scope has exactly one `@`, which LTspice then uses. It is not topology; the four nodes are the probe's connections. Nothing may follow them. *Considered:* no reference.
  9. **Edits.** `set_model` on ngspice A and N, with item 6's type check. `set_param` and `remove_param` on N, LTspice A and `@` (a list as a whole; `refnode=` and `intnode=` take a net name). `set_model_param` and `remove_model_param` on code-model and OSDI models: a vector as a whole (`"[2 1]"`), a boolean as `TRUE` or `FALSE`, a string quoted; a comment inside a vector or an `@` list over `+` lines follows decision 0019's review R3 rule. `EditError`s name the right operation: `set_param` on ngspice A (its values are on the `.model`) and on `&`, `set_value` on every new line, and LTspice A's function and the `zm` flag, which are not editable. Nodes, ports and the `%vnam` source are topology (§7.3). *Considered:* `set_function`.
  10. **The planned-letter tests** run on a mocked device matrix, since no letter is planned after M17; the `phase_2_letter.cir` rejects of both dialects and ngspice's `structure_rejects/element_line.cir`, which held an A line as the planned letter, go. An architecture test checks that no matrix entry is `planned`.
  11. **LTspice `.machine`** stays `UnsupportedConstruct` and is a named v1 exclusion: its message says "out of scope for v1", as the digital U's does.
  12. **Corpus.** The families `ngspice/code_models`, `ngspice/osdi_devices` and `ltspice/special_functions`: the maintainer's LTspice schematics with their `-netlist` exports, base ngspice netlists written for M17 (provenance confirmed by the maintainer, 2026-11-10), all xdylanm, MIT, and variants that change one form each. The ngspice distribution's examples are not copied.
  13. **Where the code goes.** The rules are in `model/_rules_special.py` (P12); the edits extend the existing operation modules. No new terminal is outside interegular's collision check.
- **Consequences:**
  - This record amends architecture §4 (`model-types.json` and `model_types.py` in the model package), §5.3 (the new nodes, `CodeModelPort`, `CodeModelConnection` and the code-model `.model` values), §6.3 rule 14 (N uses the boundary rule), §7.2 (the model-type rule for A and N, and the edits of item 9), decision 0015 item 3 (`%vnam` is a controlling reference) and plan section 8, point 2 (the digital U). Item 3 is an exception to decision 0002.
  - NG-COD-001, NG-OSD-001, LT-SPF-001, LT-FRA-001 and LT-FRP-001 are new spec entries; NG-MOD-001, NG-UNS-001, NG-URC-001, LT-UNS-001 and LT-MCH-001 change. Every refusal a solver runs has a row in that dialect's `discrepancies.md`.
  - The signature snapshot is unchanged: the new entries come only from new lines. The tree snapshot adds the M17 files, loses the two planned-letter rejects, and 17 rejected files list the two new letters among their expected terminals.
  - The probes found what the task list did not have: the manual's own `%vd [1 2 3 4]` (a differential type before a vector, loaded as pairs); `NULL` in any case; `%vnam` inside a vector stops ngspice; LTspice refuses a probe with an analyzer in `zm` mode, and a `.fra` run needs `fstart=` and `fend=` beside `flist=`; and r2_cmc ignores its model's `rsh=`.
